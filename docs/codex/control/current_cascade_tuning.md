# Iq电流—姿态—速度三环控制

## 当前结构

速度PI输出目标倾角rad，姿态PD输出平衡电流A；转向PI并行输出差动电流A。平衡电流优先分配，左右目标分别为公共电流减/加差动电流。BSP进行两相采样、Iq投影、单Iq PI和第十一课六扇区SVPWM，不建立Id环。Ud=0不表示实际Id为零。

- `BSP/Motor/current_sense`：ADC1四通道、逐路零偏、相电流和采样时间。
- `BSP/Motor/current_control`：Iq投影和电流PI，纯函数/显式状态。
- `BSP/Motor/svpwm`：六扇区占空比计算，左右共用一张表。
- `BSP/Motor/motor_foc_service`：传感器、对齐、双轮状态、PWM和公共GPIO12所有权。
- `Middlewares/Control/balance_controller`：外环、目标斜坡、电流分配和饱和反馈。
- `Middlewares/FreeRTOS/application_tasks`：唯一运行调度者。

仅BSP使用必要类：CheckedEncoder包装库错误返回；第三方对象不暴露给Middlewares。正常运行不调用库loopFOC/move；BLDCMotor仅参与启动对齐。编码器方向来自对齐，轮子安装方向由ForwardSign单独定义；当前M0/M1的ForwardSign均为-1，目标电流及车辆轮速/Iq/Uq坐标同步反向。电角度仍使用对齐得到的encoder_direction，相电流极性仍为+1，不能随车辆方向一起取反。该配置按用户实机方向反馈修改，新的整车方向仍待复测。

## 单位、参数与公式

控制内部用rad、rad/s、rad/s²、A、V、s；IMU当前接口和通信边界保留deg。前进、前倾、右轮更快产生的偏航为正；实际IMU与机械安装方向待实测。相电流遥测为桥臂到电机坐标，Iq、Uq及目标电流为车辆前进坐标。

`Ialpha=Ia; Ibeta=(Ia+2Ib)/sqrt(3); Iq=Ibeta*cos(theta)-Ialpha*sin(theta)`。
库dc_current是带符号的电流矢量幅值，不能代替Iq投影。

第十一课运行时P=5、I=200、D=0，两个库均以秒计算梯形积分：

`integral_v += Ki * dt_s/2 * (error_a + previous_error_a)`。

采用Kp=5 V/A、Ki=200 V/(A*s)，不按1kHz再次换算。在1ms周期，Ki*dt/2为0.1；连续0.1A误差每周期积分增加0.02V。首次复位后的积分周期使用配置的1ms，其后用相电流批次开始时间之差；非法周期报错，不以1ms覆盖错误。条件积分按实际梯形增量方向判断，输出饱和时禁止继续累积，允许退出饱和；停止清零。

## SVPWM与采样

SVPWM保留第十一课正负Uq处理和六扇区表；t1/t2/t0是周期比例，不是秒。计算前检查有限数和母线值，拒绝超线性区请求；仅浮点舍入误差允许最终占空比微调。使用MCPWM20kHz，不复制Arduino LEDC的30kHz/8bit写法。

ADC1四路12bit/12dB，使用IDF line-fitting标定，Vref缺省回退1100mV。公共使能关闭时平均1000组零偏，检查偏置1300~1900mV、峰峰噪声<=100mV；运行输入150~2450mV。换算为 `(mv-offset_mv)*0.001/(0.01*50)`。以上阈值为候选范围，需确认真实偏置与噪声。

每批只滤波一次，日志读取不推进滤波器。两相及双轮顺序采样，不声称PWM同步。ADC/I2C失败、样本过期、浮点异常、相电流超限使双轮故障关闭。

## 调度与停止

BMI160加速度计与陀螺仪ODR均为800Hz（0x40/0x42低四位0x0B），保留原量程和带宽位；软件每5ms读取最新12字节帧并更新姿态控制，目标200Hz。没有FIFO平均或DRDY同步，振动混叠和群延迟仍需实测。互补权重按alpha=0.098/(0.098+dt)计算，dt以秒计；2ms时alpha=0.98，5ms时约0.95146。首帧直接使用加速度计倾角。

ODR编码已对照[Bosch BMI160 SensorAPI](https://github.com/boschsensortec/BMI160_SensorAPI/blob/master/bmi160_defs.h)；低四位0x0B在加速度计和陀螺仪中均表示800Hz。

1kHz定时器只通知ControlTask，任务按实际时间执行：命令检查→到期IMU及倾倒检查→编码器→到期外环→本周期Iq目标→相电流→PI→SVPWM→快照。姿态用5ms绝对截止点，外环累计10ms；不回放积压通知。目标频率不是实测带宽。

双轮编码器读取耗时限2ms，编码器开始到PWM提交限4ms；ADC批次读取耗时限2ms，电流采样开始到PWM提交单独限2ms，PWM前后均检查两种年龄。编码器4ms是用户授权的低速调试候选值，不是实测稳定裕量；遥控目标2rad/s并非实际轮速硬上限。任务入口、执行和姿态周期间隔保护仍为10ms，电流积分使用实际批次间隔。I2C/ADC在任务内同步阻塞，超时检查只能在调用返回后处理，软件保护不具有硬实时关断保证。

初始化完成后ControlTask独立运行零速/零偏航闭环，不等待BLE连接。balancing表示本地使能，driving表示目标在控制就绪后收到且年龄小于300ms；无有效目标时保留零速环及积分。首次平衡时重置控制状态。首帧姿态以加速度计角度建立基准，先检查倾倒再执行电流输出。

遥控超时和BLE断连令速度/偏航目标归零，继续零速平衡；松手、失焦和后台由网页发送零目标。BLE不负责电机启停或故障处置。传感器故障、倾倒超过30°和时序异常仍由ControlTask锁存关闭，须复位恢复。启动对齐仍可能运动。

当前源码硬件确认门为true，本次重构未修改它。上电初始化可能执行对齐；相序、方向、量程、几何和参数仍需实板核验。本次未烧录或运行电机。

## 观测协议

BLE主服务.001，只保留.006 WRITE命令D,seq,steering,throttle，百分比±100。BleTask转换为速度±10rad/s及偏航±0.5rad/s（速度目标在控制器内仍按现有±2rad/s限幅），经静态队列发送ControlTask；正转向仍对应左轮更快，即负偏航。不保留状态或错误回传。

TCP协议为 `#balancing_vehicle_tcp,v2`，每行21列：原七列保持顺序，追加左右实测Iq、左右实际Uq、左右三相电流、current_dt_s、current_sample_age_us、current_saturated、current_valid。客户端应读取列名和版本，不假定仍为七列。停止时current_valid=0，零值不是有效电流测量。发送缓冲768字节；格式化和网络只在Wi-Fi任务执行。

队列只保留最新状态，不能用于无损波形或故障峰值记录。PI饱和和目标限幅逐周期汇总到外环窗口，冻结外环积分。

## 软件验证与台架验收

当前测试入口为tests/diagnostics，生产控制/电机/IMU代码配合硬件stub验证；保留故障注入、零速平衡及电流路径，新增命令时效边界。网页测试为tests/ble_web.test.cjs。结果见[BLE任务验收](../tasks/ble_motion_task.md)，不代表实板闭环或时序通过。

上板顺序：

1. 限流电源、保护架；公共使能关闭时检查四路零偏和实际相线/极性。
2. 核对编码器方向、电角度零点、IMU轴和左右前进符号。
3. 单轮±0.1~0.2A，再双轮；观察Iq、相电流、Uq、饱和退出与振荡。
4. 加入姿态环，再速度与转向；验证目标倾角、平衡优先分配和零速目标。
5. BLE/Wi-Fi负载下测量WCET、抖动、样本年龄、漏周期、栈水位和命令归零与故障禁能延迟；注入ADC/I2C错误。
6. 验证公共电源关闭后的实际桥臂行为、滑行距离和供电衰减；有硬件证据后再逐项调整参数/启用前馈。

电机硬件、实际闭环稳定性、对齐期过流保护、运行欠压、硬件过流、时序与栈余量均为Unverified。
