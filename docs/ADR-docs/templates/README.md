# ADR 使用规范：当前项目说明与只读模板

本套 ADR 用于帮助人和 AI 理解当前项目。`architecture.md` 描述当前功能、入口、模块、运行链路与数据流；`architecture-decisions.md` 解释当前有效的设计理由、约束和取舍。两份文档只维护当前状态，不承担历史记录职责。

## 导入项目

将本目录的三个文件原样复制到项目的 `docs/ADR-docs/templates/`，作为只读模板。再将其中两份架构模板复制到外层，作为可填写的项目文档：

```text
docs/ADR-docs/
├── templates/                         # 只读，不填写项目内容
│   ├── README.md                     # 本规范
│   ├── architecture.md               # 原始架构模板
│   └── architecture-decisions.md     # 原始决策模板
├── architecture.md                   # 项目实际架构
└── architecture-decisions.md         # 项目当前决策
```

导入前检查目标路径；已有文件不得直接覆盖。已有项目文档应按本模板整理当前有效内容，并核对源码与链接。实际文档之间使用外层相对链接，不链接到模板中的占位内容。

## 强制规则：模板只读

1. 导入项目后，`docs/ADR-docs/templates/` 中的全部文件内容只读。人和 AI 均不得修改、追加、删减、替换或重新生成这些文件，也不得在其中填写项目情况。
2. 只允许在外层项目文档的指定填写区维护当前事实。`architecture.md` 可填写 `verification` 值和“项目真实文档”区域；`architecture-decisions.md` 可在“项目真实决策开始”标记之后维护主题。其他规范、字段定义和示例保持原样。
3. 必须按照模板操作：保留规定章节、字段、顺序及表格列；按模板重复功能、链路和决策条目，填写占位符与图表。不适用项明确说明原因，未知项明确标注，不得为了适配项目而改写模板或另创结构。
4. 模板不适用时，应报告具体缺口，不得在项目内自行修改模板。模板维护属于独立工作，只能在模板源仓库中根据用户明确的模板维护请求进行；日常项目开发、重构和文档同步不授权修改模板。
5. 模板只读不等于项目文档只读。项目实际文档应随当前代码及时更新，但必须遵守填写边界。

这里的“只读”是强制使用规则，不依赖 Windows 文件只读属性；不得通过取消文件属性绕过规则。

## 只记录当前项目情况

- 只保留当前架构、当前决策及有效依据，不写变更日志、旧方案、前后对比、废弃决策、迁移过程或历史快照。
- 内容变化时，直接更新对应章节、图表和决策；删除不再有效的描述与引用，不按日期追加记录。版本历史交给 Git 等版本控制系统。
- 保留帮助理解项目的功能导航、阅读入口、依赖关系、运行协作、数据所有权、设计理由和验证边界。
- 当前方案的收益、代价、成立条件及重新评估触发条件可以记录；待实施计划不得写成已实现事实。
- 代码事实、设计理由和实测结果分别核对；源码检查不能代替编译、测试、仿真或硬件验证。当前无法确认的内容写入 `Unknown / Unverified`，解决后更新正文并移除已解决条目。

## 项目工作流程

1. 对涉及多个模块、Task、数据流或公共接口的修改，先阅读 `docs/ADR-docs/architecture.md`，再核对相关源码。
2. 涉及现有架构选择时，读取 `docs/ADR-docs/architecture-decisions.md` 中的相关当前决策。
3. 当前结构、入口、运行关系或数据流变化时，更新外层 `architecture.md`。
4. 当前策略、约束或设计理由变化时，更新外层 `architecture-decisions.md`；两类变化同时发生时同步更新。
5. 项目文档修改必须与对应代码修改处于同一次 change。初始化文档或修正文档与源码不一致时，依据当前源码核对，无需为文档而修改代码。
6. 使用 Architecture Change Gate 检查遗漏，仅将结论用于更新当前内容，不积累检查日志。
7. 完成后核对两份文档与当前实现、图表和链接的一致性，确认填写区外内容保持原样，且 `templates/` 文件内容与导入时一致。

## 纳入项目 AGENTS.md 的规则

导入后，将以下规则加入项目实际生效的 `AGENTS.md`；已有同类规则时合并，保留其他项目要求：

```markdown
## ADR

- ADR 只记录当前项目情况，不记录历史。先阅读 `docs/ADR-docs/architecture.md`；涉及设计选择时再读 `docs/ADR-docs/architecture-decisions.md`，并核对实际源码。
- `docs/ADR-docs/templates/` 中所有文件均为只读模板，导入后禁止修改、追加、删减、替换或重新生成。不得通过修改模板适配项目。
- 实际项目内容仅填写在外层两份文档的指定填写区，严格遵循模板章节、字段、顺序及表格列；填写区以外内容保持原样。不适用项说明原因，未知项明确标注。
- 架构变化时直接更新当前描述，删除失效内容并修正引用；不追加历史日志。当前结构与当前决策须和对应代码在同一次 change 中同步。
- 区分源码事实与实测结论；未确认内容记录为 Unknown / Unverified，解决后更新正文并移除对应待确认条目。
- 完成前检查模板内容未变、项目文档格式符合模板，并核对当前源码、文档及链接的一致性。模板存在缺口时报告，不得自行修改。
```
